# MeshCentral-AutoOnboard

Кастомный плагин для MeshCentral: автоматически прогоняет заданную **последовательность
PowerShell/BAT/Bash скриптов** на каждом **новом** устройстве в момент первого подключения
его агента к серверу — то, чего нет ни в стандартном MeshCentral, ни в ScriptTask.

## Возможности

- Несколько скриптов по очереди, в заданном порядке (шаг 2 стартует только после успеха шага 1).
- Для каждого шага: количество повторов при ошибке, задержка между повторами, таймаут выполнения,
  поведение при исчерпании попыток («остановить всю цепочку» или «пропустить и идти дальше»).
- Если устройство офлайн (выключено/нет сети) — шаг просто ждёт и автоматически выполняется, как
  только устройство подключится к серверу (без вашего участия).
- Самовосстановление: если агент «пропал» посреди выполнения шага (завис/перезагрузка) и не
  отчитался — плагин сам переотправит шаг через некоторое время после истечения его таймаута.
- Дашборд («My Server» → «Plugins» → AutoOnboard, либо вкладка **AutoOnboard** на странице
  любого устройства): статус по каждому устройству, история запуска каждого шага (успех/ошибка,
  вывод), кнопки «Повторить сейчас», «Пропустить шаг», «Перезапустить с начала».
- Кнопка ручного запуска всей последовательности на любом (в т.ч. уже существующем) устройстве.
- Необязательный webhook (POST) при завершении/провале адаптации устройства — для интеграции с
  чем угодно (Slack/Telegram-бот, тикет-система и т.п.).
- Подстановки `{{deviceName}}` и `{{nodeId}}` прямо в тексте скрипта и в пути назначения файла.
- **Шаги-файлы**: помимо скриптов, в ту же последовательность можно добавлять «доставить файл»
  — загружаете файл один раз в раздел «Файлы» (хранится на сервере MeshCentral), указываете путь
  назначения на устройстве, опционально — запустить после копирования (с аргументами командной
  строки) и «не копировать повторно, если файл уже есть». Тот же движок повторов/офлайн-ожидания/
  истории, что и у скриптов. Также поддерживается доставка по прямой ссылке (агент сам скачивает
  файл по HTTPS) — полезно для больших инсталляторов, чтобы не гонять файл через сервер.
- **«Выполнить как вошедший пользователь»** — опция у каждого шага (скрипт или запуск файла после
  установки). См. ниже, почему это нужно и как работает.

## Важный нюанс: скрипты выполняются от SYSTEM, а не от пользователя

Это не баг ScriptTask или этого плагина — так работает MeshCentral в принципе: агент — это
служба Windows, выполняется от имени SYSTEM, и **любой** способ запустить скрипт через агент
(хоть встроенный «Run Commands», хоть ScriptTask, хоть AutoOnboard) выполняется от SYSTEM. У
самого MeshCentral есть галочка «Must run as user» в Run Commands — но это известный,
подтверждённый баг: она не переключает контекст (см. issue #4949 в репозитории MeshCentral).

Для большинства админских задач (установка софта, реестр HKLM, службы) SYSTEM не проблема — он
даже удобнее, не зависит от того, залогинен ли кто-то. SYSTEM мешает только тогда, когда скрипту
реально нужен контекст вошедшего пользователя (HKCU, что-то, что должно быть видно юзеру на
экране).

Для этого случая в каждом шаге (скрипт-PowerShell, либо запуск файла после установки) есть галочка
**«Выполнить как вошедший пользователь»**. Она автоматически оборачивает скрипт кодом, который
через модуль [RunAsUser](https://github.com/KelvinTegelaar/RunAsUser) (стандартное, проверенное
временем решение в RMM/MSP-сообществе, основано на token impersonation) временно «перепрыгивает»
из SYSTEM в сессию вошедшего пользователя. **Важно:** при первом запуске на устройстве это требует
доступа в интернет (модуль ставится из PSGallery, если его ещё нет) — если у ваших машин
ограничен/нет интернета, можно один раз доставить `RunAsUser.psm1` на все устройства заранее через
обычный шаг-файл (в постоянную папку модулей PowerShell), тогда доступ в сеть при онбординге не
понадобится. Также эта опция работает только для PowerShell-шагов (не для BAT/Bash).

Что касается «заблокированного ПК»: агент — служба, она не отключается, когда пользователь просто
заблокировал экран, так что блокировка экрана сама по себе выполнению скрипта не мешает (при
запуске от SYSTEM это тем более неважно). «Ждёт подключения» в дашборде означает, что агент
по-настоящему недоступен (ПК выключен, нет сети, служба остановлена) — вот тогда плагин ждёт и
повторяет попытку автоматически при восстановлении связи.

## Установка

MeshCentral устанавливает плагины только по URL на `config.json`, размещённый в вашем
собственном репозитории (точно так же, как вы ставили ScriptTask). Поэтому:

1. Создайте **публичный** репозиторий на GitHub, например `meshcentral-autoonboard`, и загрузите
   в него все файлы из этой папки, сохранив структуру:
   ```
   meshcentral-autoonboard/
     config.json
     autoonboard.js
     db.js
     changelog.md
     modules_meshcore/
       autoonboard.js
     views/
       admin.handlebars
       user.handlebars
   ```
2. Откройте `config.json` в репозитории и замените `YOUR_GITHUB_USERNAME` на ваш логин GitHub
   (3 места: homepage, changelogUrl, configUrl, downloadUrl, repository.url) и, если ваша основная
   ветка называется `master`, а не `main` — поправьте это в URL тоже.
3. Убедитесь, что в конфиге MeshCentral включены плагины:
   ```json
   "plugins": { "enabled": true }
   ```
   и перезапустите сервер.
4. В веб-интерфейсе: **My Server → Plugins → Download plugin**, укажите URL вида
   `https://raw.githubusercontent.com/ВАШ_ЛОГИН/meshcentral-autoonboard/main/config.json`,
   установите и включите плагин.
5. **Прежде чем включать автозапуск**: зайдите в админ-панель плагина (клик по AutoOnboard в
   списке плагинов, либо `/pluginadmin.ashx?pin=autoonboard&admin=1`) и нажмите
   **«Отметить все текущие устройства как уже настроенные»**. Это защитит вашу текущую рабочую
   технику от случайного повторного прогона скриптов адаптации при следующем их переподключении —
   плагин иначе не отличает «старое» устройство от «нового» и по умолчанию сработает на всех.
6. Добавьте шаги (скрипты и/или файлы) в разделе «Последовательность адаптации» и убедитесь, что
   галочка «Автозапуск адаптации для новых устройств включён» отмечена.

## Про загрузку файлов

Файл загружается из браузера прямо в админ-панели плагина (раздел «Файлы»), кусками, через тот же
канал связи, что и остальные действия плагина — без отдельной настройки на сервере. Хранится он на
диске сервера MeshCentral (папка `plugin-autoonboard-files` рядом с `meshcentral-data`), а не в
базе данных. Комфортно для файлов примерно до 50-100 МБ; для больших инсталляторов лучше
использовать режим «По прямой ссылке (URL)» в шаге — тогда каждое устройство скачивает файл само
напрямую, без промежуточного хранения на сервере меша.

## Важно понимать

- Это самописный плагин, который я не тестировал на живом сервере MeshCentral (у меня нет
  доступа к вашему серверу) — логика построена на проверенном коде ScriptTask, официальной
  документации плагинов MeshCentral и реальном исходном коде самого MeshCentral (хуки, протокол
  агента), но перед использованием на всём парке рекомендую сначала проверить на 1-2 тестовых
  машинах — особенно шаги с загрузкой/запуском файлов и опцию «выполнить как пользователь».
- Официально плагины MeshCentral не поддерживаются разработчиком самого MeshCentral — это
  предусмотренный, но «на свой страх и риск» механизм расширения.
- Хранилище — отдельный файл NeDB (`plugin-autoonboard.db` в папке `meshcentral-data`) плюс папка
  `plugin-autoonboard-files` для загруженных файлов; от ScriptTask не зависит.
